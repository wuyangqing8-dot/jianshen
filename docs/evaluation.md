# Evaluation protocol

1. 固定相机视角、镜头距离和分辨率；记录硬件、操作系统、模型 SHA、输入大小、推理提供程序。
2. 至少覆盖不同身高/体型、光照、衣着、遮挡；所有录像须受试者主动同意，不能默认记录。
3. 每段由人工标注动作类别、起始/底部/结束时刻、次数、错误类型。正常动作、半程动作、遮挡和多人情况分别记录。
4. 动作结束事件按预先声明时间容差（示例0.5 s）一对一匹配，报告 TP/FP/FN、precision/recall、计数绝对误差。仅比较总次数会漏掉相互抵消的误报漏报。
5. 自动动作分类已有保守的时序规则，输出可能是 unknown；先报告覆盖率，再报告仅在已分类样本上的准确率及各类混淆矩阵。`evaluate_actions.py` 提供指标，但没有真实标注集，不能声称分类准确率。
6. 专家评分 CSV: system_score,expert_score。至少两名评分者，先检查评分一致性；按受试者划分训练/验证/测试，避免同一人的相邻帧泄漏。
7. evaluate_scores.py 报告 Pearson/Spearman/MAE/RMSE；常数列相关系数返回 null。r>0.85 仅为目标。
8. benchmark.py 是重复图片吞吐测试；benchmark_camera.py 在用户硬件测摄像头/推理 FPS、CPU、内存；UI FPS 在应用中独立显示。不能混淆理论吞吐与摄像头采样。

旧系统 58/60、57/60、56/60 和30.1 FPS仅为用户提供的历史参考，没有用于本次系统验证。
9. `evaluate_phases.py` 按状态匹配阶段时刻；`evaluate_errors.py` 计算各错误的多标签精确率/召回率。训练/测试中生成的合成关键点仅验证软件逻辑，不能作为实际识别率数据。
